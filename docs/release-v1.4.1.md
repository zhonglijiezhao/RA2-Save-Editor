# v1.4.1 — 大存档不再卡死 ＋ 武器表可以导出成表格了

这一版只有两件事，但都是玩家直接提的：

> 玩家 2026-10-28：「这个存档打开就卡死」（`SAVE5DC8.SAV`，5250 条记录 / 1930 条触发）
> 玩家 2026-10-28：「这个存档中的武器能提取出来吗，尤其是非原版的武器」

---

## 1. 修：这种存档以前永远打不开

不是死循环，是 **O(n²)** —— 每画一行触发，就把整套「标签 ↔ 触发」配对重算一遍。
记录一多，加一倍行数就是四倍时间，表现出来就是卡死。

拿那份档实测：

| | 修复前 | 修复后 |
|---|---|---|
| 打开 `SAVE5DC8.SAV` | **永远打不开** | **5.8 秒**（其中解码本身 1.4s） |
| 触发列表 | — | 1930 行正常填上 |
| 手动刷新一次 | — | 1.55 秒 |

一共改了三处「每次重算」：

- **标签配对**：原来对每个标签遍历全部触发名（`startswith`）→ 改成从末尾找切点，
  只跟名字长度有关，结果完全等价。
- **标签持久性**：加缓存，并接进「换地图 / 新建触发 / 写完持久性」三个失效点
  —— 改完界面立刻能看到新值，不会拿到旧的。
- **行为链 / 事件链**：每次调用都重建 `{key: 行}` 字典（400+ 行为 × 2000+ 次调用
  = 4800 万次查找）→ 改成缓存，判据是「同一个列表对象 + 长度没变」。

> 顺带说明：那份存档的**数据是好的**。5250 条记录、1930 条触发、7237 条行为、
> 1335 栋建筑全部读对了，以前不是读不出，是界面填不完。

## 2. 新：武器表导出 CSV

「武器 · 弹头」页左下角多了一个 **「导出 CSV」** 按钮。

导出的内容：**序号 / 武器 / 伤害 / 射速 / 射程(格) / 射程(lepton) / 弹头 /
11 项克制系数 / 官方三值 / 与官方规则的差异**。

几个设计上的选择：

- 打开「只看 ≠rules」再点导出 ⇔ 只导那批「跟官方不一样」的，文件名也带 `_非原版`。
- 编码是 UTF-8 带 BOM，**Excel 双击就能打开，中文不乱码**。
- 表头前三行写清「这份存档 / 对照的是哪份 rules / 单位怎么读」——
  免得贴到论坛上以后谁都不知道基准是什么。
- 命令行同样能用：`RA2存档编辑器.exe --export-weapons <存档> [输出.csv] [--diff]`

### 为什么这张表比 rulesmd.ini 可信

存档里存的是**存盘那一刻真正生效的数值**，地图自带 INI、MIX 里的覆盖都算进去了。
所以它跟散装的 `rulesmd.ini` 不一致是正常的 —— 不一致的地方往往正是「这张图改过什么」。

举个真实例子：`SAVE5DC8.SAV` 里 `Vulcan` 的伤害是 **88**（官方 50），
而你游戏目录那份 `rulesmd.ini` 里还是 50 ⇒ 这个 88 来自**地图内联的 INI**，
不是 rules。这也再次说明：**改 rulesmd.ini 对已经存盘的存档不生效**。

## 3. 顺手查清的一件事：存档里的「非原版武器」

同一个问题带出来的结论（写在这里免得以后再查一遍）：

- 那份存档 **193 把武器，全部是官方武器名**，没有一把是 mod 自造名。
- 但 **31 把的数值和官方不同**（`Vulcan` 50→88、`BearBite` 30→18、
  `CLINTGUN` 125→8、`SABOT` 150→200、`120mmE`/`160mmE` 90→180 …），
  完整清单点「只看 ≠rules」就能看到。
- 反过来：如果你游戏目录装的是改版，那个 mod 里可能有 300+ 个武器段，
  但**这份存档只注册了它用到的那部分**。想挖 mod 新增的武器，要从 rules 那边挖，
  存档里挖不出来。

## 升级提示

- 直接从 v1.4.0 覆盖安装即可，存档格式没动，配置文件也能沿用。
- 这一版**没有**改任何写入逻辑，武器页的改值行为跟 v1.4.0 一样。

## 系统要求

| 系统 | 能不能跑 |
|---|---|
| Windows 10 / 11（64 位） | ✅ 正常 |
| Windows 8.1（64 位） | ⚠️ 理论可以，未实测 |
| **Windows 7** | ❌ **不支持** |
| **32 位系统**（含 32 位 Win10） | ❌ **不支持**（这是 64 位程序） |

Win7 跑不了不是本工具的问题，是打包用的 Python 3.13 从 3.9 起就要求 Win8.1+
（Win7 上最高只能到 Python 3.8）。在 Win7 上双击会报
`无法定位程序输入点 PathCchCombineEx` 或 `Failed to load Python DLL`。

### 第一次打开弹「Windows 已保护你的电脑」？

这是正常的 —— 本程序**没有代码签名证书**（个人项目，OV 证书一年千元级）。
点「更多信息」→「仍要运行」即可；或者右键 exe → 属性 → 勾「解除锁定」→ 确定。
如果下载的是 zip，先对 zip 做一次"解除锁定"再解压更省事。

### 不要只拷 exe

这是「exe + `_internal` 文件夹」两件套，缺一不可。只拷 exe 会报
`Failed to load Python DLL`。另外建议解压到桌面或 D 盘，
别放 `C:\Program Files` —— 程序要在自己目录写 `crash.log`，那里没写权限。
