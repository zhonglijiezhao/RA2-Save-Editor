# 探测：这份存档里的武器表（SAVE5DC8.SAV）

> 2026-10-28。玩家问：「这个存档中的武器能提取出来吗，尤其是非原版的武器」。
> 只读探测 + 顺手把「导出」做成了功能。

## 一、能提取，而且这张表就是权威值

存档里有一张**全局武器类型表**，每把武器是一个对象：

| 偏移（相对对象起点） | 内容 |
|---|---|
| `+0x00` / `+0x40` | 同一份名字，两个缓冲（`Name:XXX\0`） |
| `+0x7C` | 弹头指针（不是名字） |
| `+0x80` | **Damage**（u32） |
| `+0x8C` | **ROF**（u32，帧，越小越快） |
| `+0x90` | **Range**（u32，lepton，1 格 = 256） |

弹头对象另有 `+0x7C` 起 **11 个 double** 的 Verses（对 11 种装甲的克制系数）。

**为什么它比 rulesmd.ini 可信**：存档存的是**存盘当时生效的那份值**——地图 INI、
MIX 里的覆盖都算进去了。改 rulesmd.ini 对已经存过的档不生效，原因就在这里。

## 二、这份档的实况

```
记录 5250 条 / 触发 1930 条 / 武器 193 把 / 明文 27.2MB
```

### 1）没有一把是"mod 自造名"

193 个名字**全部**是 YR 官方武器名（`M60` / `120mm` / `PrismShot` / `CRNuke` /
`UCPara` / `AGGattling2E` …）。拿官方 `rulesmd.ini` 逐节核对，只有
`DefaultDeathWeapon` 没有独立数值段——那是引擎内置的默认武器，属正常。

⇒ **这份档不是"带了新武器的 mod 档"**。想在这份档里找"mod 新武器"，找不到。

### 4）反向发现：你那个 mod 有 152 把武器没出现在这份档里

`E:/YURI/rulesmd.ini` 里有 **344** 个武器段，这份存档只出现 **193** 个。
差的那些（`120HE` / `75mm` / `90mm` / `156mmE` / `ABFPrismGun` …）是 mod 加的，
但这一局没注册/没用到——存档里没有它们的对象。

⇒ **"提取非原版武器"如果指的是"把 mod 新增的武器挖出来"，那要从 rules 侧挖，
不是从这份存档挖。**

## 三、做成了什么功能

### CLI

```
--export-weapons <存档> [输出.ini|.csv] [--diff] [--format ini|csv]
```

- **不给路径 ⇒ INI**（红警原生格式），写到存档同目录 `<存档名>_武器表.ini`
- 给了路径 ⇒ **按扩展名**判断：`.csv` 走表格，其余走 INI；也能 `--format` 强制
- `--diff` ⇒ 只导**与官方原版**不一致的那些（含"官方根本没有"的自造武器）

### GUI

「武器 · 弹头」页左下角 **「导出…」** 按钮。文件对话框里选类型：
`INI（红警规则格式）` 或 `CSV 表格（Excel）`，按你填的扩展名走，不用点两次。
勾着「只看 ≠原版」时，默认就只导那一批。

### INI 长这样（默认格式，照原版 rules 的写法）

★玩家 2026-10-28 拿原版段落来对格式，随后按这个改：**武器 / 抛射体 / 弹头三段**，
字段顺序也照原版（`Damage → ROF → Range → Projectile → Speed → Warhead → Report → Anim
→ Burst → Bright`），段名后面带 `;武器` / `;弹头` / `;抛射体`。

```ini
[Vulcan] ;武器
; 与官方不同：伤害 50→88；射速 26→20
Damage=88
ROF=20
Range=5.5
Projectile=InvisibleLow
Speed=100
Warhead=SA
Report=SentryGunAttack
Anim=MGUN-N,MGUN-NE,MGUN-E,MGUN-SE,MGUN-S,MGUN-SW,MGUN-W,MGUN-NW

[Cannon];抛射体
Image=120MM
Arcing=true
SubjectToCliffs=yes
SubjectToElevation=yes
SubjectToWalls=yes

[ARTYHE] ;弹头
CellSpread=1
PercentAtMax=0.25
Wall=yes
Wood=yes
Verses=100%,80%,60%,100%,60%,60%,100%,100%,60%,100%,100%
Conventional=yes
InfDeath=2
AnimList=XGRYSML1,XGRYSML2,EXPLOSML,XGRYMED1,XGRYMED2,EXPLOMED,EXPLOLRG
ProneDamage=50%
```

**哪些值是存档里的真值，哪些是照 rules 抄的**（这点必须分清）：

| 字段 | 来源 | 依据 |
|---|---|---|
| 武器 `Damage` / `ROF` / `Range` | **存档实读** | `+0x80` / `+0x8C` / `+0x90` |
| 武器 `Burst` | **存档实读** | `+0x78`；52 把有 Burst 的武器对 rules 命中 49（94%），全档分布 1×155 / 2×35 / 4×3 |
| 弹头 `Verses` | **存档实读** | `+0x7C` 起 11 个 double |
| 弹头 `CellSpread` / `PercentAtMax` | **存档实读** | `+0x100` / `+0x108`（各 48/48 命中） |
| 武器 `Projectile` / `Speed` / `Report` / `Anim` / `Bright` | 照抄 rules | 存档里存的是指针而不是名字，且指针与名字对不上（见下） |
| 弹头 `Wall` / `Wood` / `Conventional` / `InfDeath` / `AnimList` / `ProneDamage` | 照抄 rules | 存档里没有对应字段 |
| 整段 `[抛射体]` | 照抄 rules | **存档里没有抛射体对象**：rules 用的 55 个抛射体名，在档内 `Name:` 命中 **0** 个 |

### 为什么不能读存档里的 Projectile / Warhead 指针

试过：武器对象 `+0x7C` 和 `+0x88` 看着像指针，但按 rules 的 `Warhead=` / `Projectile=`
分组验证，**同名的指针五花八门**（`SA` 一组里有 2 个值，`InvisibleLow` 一组里有 31 个值），
反向看一个指针又对应十几个名字 —— 对不上，说明它们不是这两个字段。

⇒ 名字层面只能靠 rules 反查（`weapon_warhead_map()`）。这也是为什么头注释里要标清来源。

### 其它有意的选择

| 决定 | 原因 |
|---|---|
| **GBK 编码、无 BOM、CRLF** | 红警是 ANSI 程序，`rulesmd.ini` 一直是 GBK。带 BOM 的 UTF-8 贴进去，第一个键名会被 BOM 污染 |
| **不写 `[WeaponTypes]`** | 那一段是注册表，顺序错一位整个武器表就错位。只在头注释里列出本档顺序供核对 |
| **每段带「与官方不同」注释** | 一眼看出哪些是这张图改过的；`--diff` 模式下段更少，直接贴就能复现 |
| **Range 写格数不写 lepton** | rules 里就是 `5.75` 这种写法，不是 `1472` |

### CSV 也能导（便于逐列对照）

```
# 存档,SAVE5DC8.SAV
# 对照规则,C://...//core//ini_builtin//rulesmd.ini
# 数值含义,伤害=点；射速=帧(越小越快)；射程 1 格 = 256 lepton
序号,武器,伤害,射速,射程(格),射程(lepton),弹头,弹头 Verses（11 项）,官方伤害,官方射速,官方射程,与官方规则的差异
2,Vulcan,88,20,5.50,1408,SA,100%; 80%; ...; 100%,50,26,5.5,伤害 50→88; 射速 26→20
```

编码 `utf-8-sig`（Excel 双击不乱码）。


## 三点五、实测：玩家自造的武器 / 抛射体 / 弹头（SAVE4AE1.SAV）

2026-10-28 玩家在 `E:/YURI/rulesmd.ini` 里新写了三样东西，然后在存档里用上了：

```ini
[9875285A]      ;武器    Damage=90 ROF=65 Range=5.75 Projectile=564187213A …
[564187213A]    ;抛射体  Image=120MM Arcing=true SubjectTo* …
[57899462AP]    ;弹头    CellSpread=.3 PercentAtMax=.5 Verses=25%,25%,15%,…,100%
```

**三个都能从存档里读出来，而且读到的值与上面写的逐项一致：**

| 对象 | 读到的东西 | 与 INI 对比 |
|---|---|---|
| `9875285A` 武器 | Damage=90 / ROF=65 / Range=5.75（1472 lepton）/ Burst=1 | ✅ 一致 |
| `57899462AP` 弹头 | Verses 11 项 = 25,25,**15**,75,100,100,65,45,60,60,100；CellSpread=0.30；PercentAtMax=0.50 | ✅ 逐项一致（含被注释掉的旧值改成 15% 那一位） |
| `564187213A` 抛射体 | 对象存在（`_type_objects` 里有），但**字段没解析**（Image/Arcing 等未做） | 导出的抛射体段是**照抄 rules** 的，值恰好相同 |

> 顺带纠正之前的一个说法：上一节写"存档里没有抛射体对象"——那是对 `SAVE5DC8` 而言
> （它的抛射体是官方名，档内确实扫不到）。这份 `SAVE4AE1` 里**自造抛射体是有对象的**，
> 只是我们还没解析它的字段。所以别把那条当普适结论。

### 由此改掉的一个真问题：差异基准

原来"非原版"是拿**当前 rules** 比的 —— 这个判据在自造武器面前**直接失效**：

- 玩家自己写进 rules 的武器，值和 rules 当然一样 ⇒ 被判成"原版"
- `--diff` 导出 **0 段**，功能对自定义武器完全没用（这次实测踩到，`n=0`）

改成拿 **`core/ini_builtin/rulesmd.ini`（官方快照）** 当基准：

- 官方里压根没有这把武器 ⇒ 标「官方原版没有这把武器（新增 / 别名）」
- 官方有但三值对不上 ⇒ 标「伤害 50→88」那种

改完这份档 `--diff` 导出 **69 把武器 + 30 抛射体 + 38 弹头 = 137 段**，
`[9875285A]` 正确出现在里面，注释写着"官方原版没有这把武器（新增 / 别名）"。

界面上的开关也从 `只看 ≠rules` 改成 `只看 ≠原版`（同一套判据，避免界面和导出对不上）。

## 四、限制（写清楚，免得当成 bug）

1. **只导"存档里存在的武器"**。`[WeaponTypes]` 里注册了但这一局没创建对象的，
   不会出现在表里（拿本档说就是 193 vs mod 的 344）。
2. **"官方列"取决于找得到哪份 rules**。存档目录没有 `rulesmd.ini` 时会用内置快照
   （`core/ini_builtin/`）；找不到则官方三列留空，其余列照常。
3. **弹头名靠 rules 反查**（武器对象里存的是指针，不是名字）。没有 rules 时这一列空。
4. 导出**只读**，不碰存档（自检里用明文 hash 前后一致来钉这一条）。
