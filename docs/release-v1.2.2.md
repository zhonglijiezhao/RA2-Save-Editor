# v1.2.2 — 打开大存档提速 6 倍（读条 / 懒解析 / 两个全档扫描改成只扫一次）

这一版没有新功能，全是速度。同一份大任务档（文件 3.4 MB / 明文 26.2 MB / 1448 单位 / 1113 建筑 / 495 条触发记录）：

| 项 | 改前 | 改后 |
|---|---|---|
| **打开存档总计** | **~19 秒** | **~3 秒** |
| 载入后六步（触发表 / AI 页 / 地图页…） | 17.4 秒 | 1.7 秒 |
| 「作战小队」页刷新 | 2.59 秒 | **0.08 秒** |
| 触发表刷新 | 5.09 秒 | **0.10 秒** |
| 切到「地图 / 选位」页（首次） | 9.3 秒 | **0.38 秒** |

## 1. 打开存档有读条了，不再像卡死

载入拆成 6 步，每步之间让出一次事件循环（窗口不会「未响应」，进度条真的会走）：

```
正在载入 SAVE4823.SAV：挂载地图…（1/6，已用 0.3 秒）
正在载入 SAVE4823.SAV：解析触发器列表…（2/6，已用 1.1 秒）
…
已载入 SAVE4823.SAV：495 条记录 · …（总耗时 3.0 秒）
```

以前这十几秒里 Tk 主线程被占死 —— 进度条自己也不动，所以看着完全像卡死。

## 2. 地图页改成「切过去才解析」

开档时只记下地图路径，**不解析**。等你切到「地图 / 选位」页才解析+渲染（切页前状态栏会提示）。
开档多半先看触发表/单位，这一步以前白等 9 秒。

## 3. ★真凶：一个逐字符的 base64 解码器

原本以为慢在 LZO 解压（实测单块只要 0.001 秒）。真正吃掉 **8.75 秒**的是把 22 万字节的 base64
**逐字符扫一遍**的那个函数。现在改用标准库解码（段定位仍沿用原来的判定，因为 base64 数据里也会出现 `[`），
LZO 换成项目自带的 C 后端。

**8.8 秒 → 0.03 秒**，而且解出的 42901 格与旧实现**逐条完全一致**（自检里直接断言 `tiles_fast == slow`）。

附带一个好处：打包后的 exe 地图页**不再依赖外部技能目录**（以前玩家机器上没那个目录，地图就没有地形）。

## 4. 两个「全档扫描」被调了几百次

- 每支小队显示「出现于 12 (54,86)」都要重新定位一次路径点表 —— 定位一次要在 26MB 明文里找锚点
  再校验 702 项坐标，单次 19.6 ms，125 支小队 = **2.4 秒**；
- 每条触发都要重新扫一次 CellTag 对象表（92 个对象 ⇒ 92 次全档查找），单次 14.3 ms，98 条 = **1.4 秒**。

两处都改成缓存（缓存键 = 明文长度：改路径点是原地改 4 字节不失效，增删对象必然改长度 ⇒ 自动作废）。
上面那张表里的 32 倍、50 倍就是这么来的。

## 关于「作战小队」页只显示作者写的

这版**没有改显示规则**——因为「只显示地图定义的（引擎每局生成的默认隐藏）」本来就是默认行为，
计数条会写「已隐藏引擎生成的 383 个（勾选左边可看）」。这一版只是让它**读得快**。

## 自检

新增 `_selftest_ev272.py`（21/0）与 `_selftest_ev273.py`（22/0）。其中最关键的两条：

- 新的快速解码与旧实现解出的 **42901 格逐条完全一致**；
