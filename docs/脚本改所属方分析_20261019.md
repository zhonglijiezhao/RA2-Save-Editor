# 定案：这套"援军变治安官"是怎么搭的（DS老师 2026-10-19）

## 一句话

作者把「改所属方」写进了 **TeamType 的脚本**（脚本动作 20，参数 13 = Special 治安官），
所以**这支小队每被刷出来一次，就会转一次** —— 这不是一次性触发，是**随队携带**的行为。

## 为什么"后面拿到同类兵会变待机"

1. 转换**在队伍上**，不在触发器上 ⇒ 只要刷出的是 **归治安官版**，新兵必然立刻变治安官；
2. 这些队 `Max=5`，而 `行为 4 建立作战小队` 会**复用已存在的实例**——
   只要之前那支（雕像）还活着，后来的兵就更容易"加入旧队"而不是新建队；
   这就是"有概率"的来源：**看当下还有几支同名队活着**。
3. 「编号」本身不改触发/脚本，它影响的是**这些单位还活着、还被引擎算作那支队**
   （玩家编组后单位更不容易被清理），所以给人的感觉是"编过号就更爱复发"。
   ⇒ 相关性来自"队伍实例还活着"，不是编号本身有魔力。

## 怎么修（按代价从小到大）

1. **不要复用**：把"归治安官"那 19 支队复制成**只给那一条触发用**的专用队，
   其它地方发兵一律用 Clone 版（20→0）；
2. 给"归治安官"的队 **Max 改 1**，并在用完的触发里加 `行为 5 解散作战小队`（或 `54 禁止触发`）；
3. 想保留"发完兵后过一阵变治安官"的效果，就别写在队脚本里，改成一发一次性触发器：
   `行为 14（对单位标签，参数 13）` + `行为 54 禁止触发`，且标签只挂那一个单位；
4. 队列里已经"待机"的雕像，最好用 `行为 119 摧毁特定所属方`/手动清掉，别让它们一直占着实例槽。

> 提醒：脚本动作 20 的参数同样是**引擎国家索引**（12=Neutral 平民、13=Special 治安官），

# 追加：`忽视分组` = INI 的 `LooseRecruit`，以及一份可执行的补丁（2026-10-19 11:0x）

`LooseRecruit`（忽视分组）的语义就是"**队员可以脱离当前编组被单独招募/重组**"。

## 2. 为什么"编队"会把 bug 概率放大

三个条件叠在一起才会串味：

1. **转换在队脚本里**：`[0] 20 → 13`，这支单兵队每次被创建都会把成员改成治安官；
2. **`Max=5`**：同一个 TeamType 允许同时存在 5 支实例，引擎会把后来的兵**并进还活着的旧队**；
3. **`LooseRecruit=yes`（忽视分组）+ 玩家编队**：队员可以被单独挖出来/重组，
   玩家一编组，这些单位在引擎眼里更"粘"在那支队上，旧实例迟迟不消失。

⇒ 于是"后面拿到的同型兵"更容易走"并入旧队"这条路，而旧队的脚本已经执行过（或被重置），
表现就是**一出生就是治安官、站着不动**，而且**看当时还剩几支旧队活着**——所以是"有概率"。

## 3. 补丁脚本

`_patch_zhiandui.py`（本目录）：自动找出"脚本含 20→12/13"的所有 TeamType，然后：

- `Max` → 1（不再复用实例）
- `LooseRecruit` → no（关掉忽视分组）
- `Full`（预装载）→ no

★**所有替换都保持字节长度不变**（`yes`→`no ` 补空格），所以地形/单位那些二进制段一个字节都不动。

```
python _patch_zhiandui.py "原图.map" "补丁.map"
```

本图实测：命中 **12 个脚本 / 29 支小队**，只改了 **29 个字节**（全是 `Max=5`→`Max=1`），
文件长度 1,390,840 字节前后一致，逐字节 diff 只有这 29 处。

> 注意：本节验证用的是 `地图修复器\all01umd_fixed.map`；玩家截图里那版 ID 略有不同
> （`ETUGUISHUBUDUI12H17` vs `ETUGUISHUBUDUI1ZHI7`），补丁脚本对**任意版本**都能跑，
> 按"脚本含 20→12/13"识别，不依赖具体 ID。
