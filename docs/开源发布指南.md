# 开源发布指南（写给第一次用 GitHub 的人）

> 目标：把这份代码变成一个**别人能在 GitHub 上看到、下载、提 Issue、提 PR** 的开源项目。
> 你不需要会 Linux，也不需要懂 Git 原理，照着做就行。

---

## 0. 先搞清三件事

| 名称 | 是什么 | 类比 |
|---|---|---|
| **仓库（repo）** | 一个目录 + 它的全部修改历史 | 一个带"时光机"的文件夹 |
| **本地仓库** | 你电脑 `RA2存档编辑器\` 目录里的 `.git` | 你的工作台 |
| **远程仓库** | GitHub 上的那个网页 | 云端的公开展示柜 |

- `commit` = 给当前状态拍一张快照（本地）
- `push` = 把快照上传到 GitHub（**这一步之后全世界都能看到**）
- `Release` = 在仓库里挂一个"下载区"，用来放打包好的 exe

**开源 ≠ 放弃版权。** MIT 协议只是允许别人自由使用/修改/再发布，版权仍然是你的。

2. `README.md` 顶部的版本号（现在是 `v1.0.0` / 内部构建 `p138`），以后每发一版改一次

## 2. 在 GitHub 上建一个空仓库

1. 打开 https://github.com ，注册/登录
2. 右上角 `+` → **New repository**
3. 填：
   - **Repository name**：`RA2-Save-Editor`（名字里别用中文和空格，最稳；也可以叫 `ra2yr-save-editor`）
   - **Description**：`红色警戒2/尤里的复仇 存档编辑器（Windows, Python+tkinter）`
   - **Public**（公开，这才是开源）
   - ⚠ **不要**勾 "Add a README file"、**不要**选 .gitignore、**不要**选 license
     （你本地已经有这些文件了，勾了会在推送时冲突）
4. 点 **Create repository**，页面会给你几个命令 —— **只看 HTTPS 那一段**

## 3. 把本地仓库连到 GitHub 并推送

在项目目录里执行（把 `你的用户名` 换成你的 GitHub 用户名）：

```bash
cd "C:/Users/zhao5/Desktop/1RA2存档分析工具/RA2存档编辑器"

git branch -M main                                  # 主分支叫 main
git remote add origin https://github.com/你的用户名/RA2-Save-Editor.git
git push -u origin main
```

### 第一次推送会要求登录（两种方式，任选）

**方式 A：浏览器弹窗登录（最省事，推荐）**
Windows 版 Git 自带 `Git Credential Manager`，执行 `git push` 时会**弹出一个浏览器窗口**，
点 "Sign in with your browser" → 登录 GitHub → 授权。之后就不用再登了。

**方式 B：用 Personal Access Token（公司电脑弹不出窗口时用）**

1. GitHub 右上角头像 → **Settings** → 最下面 **Developer settings**
2. **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**
3. Note 随便写（如 `ra2-editor-push`），Expiration 选 90 天，勾上 **`repo`** 这一项
4. 生成后**立刻复制**那串 `ghp_xxxxx`（关掉就再也看不到）
5. `git push` 时：
   - `Username`：你的 GitHub 用户名
   - `Password`：**粘贴 token**（不是账号密码！GitHub 从 2021 年起就不支持密码推送了）

> 如果提示 `remote: Support for password authentication was removed`，就是用了密码，改成 token 即可。

推送成功后刷新 GitHub 页面，代码就上去了。

## 4. 发一个 Release（放打包好的 exe）

GitHub 仓库本身**不该存 32MB 的打包产物**，打包结果放在 Release 里：

1. 本地把 exe 打成 zip（只装 exe + `_internal` 文件夹）：
   ```bash
   cd "C:/Users/zhao5/Desktop/1RA2存档分析工具/RA2存档编辑器/build_dist"
   # 右键 RA2存档编辑器 文件夹 → 压缩为 zip，命名 RA2存档编辑器-v1.0.0.zip
   ```
2. GitHub 仓库页右侧 **Releases** → **Create a new release**
3. **Choose a tag** → 输入 `v1.0.0` → 点 "Create new tag"
4. Title 写 `v1.0.0`；说明里写这一版有什么（可以从 `git log` 抄几条）
5. 把 zip 拖到 "Attach binaries by dropping them here"
6. 点 **Publish release**

之后 README 里"到 Releases 下载"那句话就真的能点了。

## 6. 新手最容易踩的 6 个坑

| 报错 / 现象 | 原因 | 处理 |
|---|---|---|
| `remote: Support for password authentication was removed` | 用账号密码当密码了 | 改用 Personal Access Token（第 3 节方式 B） |
| `fatal: remote origin already exists` | 已经加过远程地址 | `git remote set-url origin https://github.com/你/仓库.git` |
| `! [rejected] main -> main (fetch first)` | GitHub 上已有你本地没有的提交（多半是建仓时勾了 README） | `git pull --rebase origin main` 之后再 `git push` |
| `error: RPC failed; HTTP 413` 或推得极慢 | 推了不该推的大文件（打包产物/游戏文件） | `git status` 检查；确认 `.gitignore` 生效后 `git rm -r --cached 那个目录` 再提交 |
| 网页上中文文件名变成乱码 | 未开 `core.quotepath` | `git config --global core.quotepath false` |
| 想撤销最近一次提交（还没 push） | — | `git reset --soft HEAD~1`（文件改动会保留） |

> **最危险的一步是"提交了游戏文件"**：一旦进了历史，删掉文件也还在历史里。
> 所以每次 `git add` 前看一眼 `git status`，出现 `.SAV` / `.MAP` / `.mix` / `gamemd.exe` 就停下。

## 7. 想换协议？

现在是 **MIT**（最宽松：别人可以随便用、改、商用，只要保留版权声明）。

如果你希望"**别人改了也必须开源**"，就换成 **GPL-3.0**：

1. 打开 https://www.gnu.org/licenses/gpl-3.0.txt ，全选复制
2. 用它替换 `LICENSE` 文件全文
3. `README.md` 里 `MIT` 改成 `GPL-3.0`
4. `git add -A && git commit -m "docs: 协议改为 GPL-3.0" && git push`

⚠ 一旦发布过就不能随便收回了（别人已经按旧协议拿到代码）。

## 8. 发布前最后自检清单

- [ ] `LICENSE` 署名改成了自己的
- [ ] `git status` 里没有游戏文件 / 存档 / 打包产物
- [ ] 仓库里**没有** `_re/gamemd.exe`、`build_dist*/`、`*.SAV`、`*.MAP`（`git ls-files | grep -iE "sav|map|mix|gamemd"` 应该没输出）
- [ ] `README.md` 能照着跑通一次（至少"从源码跑"那一段）
- [ ] 自检脚本至少跑通一个（`python _selftest_ev192.py`）
- [ ] 知道自己的协议是什么、意味着什么（第 7 节）

搞定，你就是一个开源项目的作者了 🎉
