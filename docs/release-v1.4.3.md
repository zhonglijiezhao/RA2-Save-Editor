## 1. 修：一个未知类型不再拉倒整张行为表

**症状**：`SOV01UMD.sav` 里 166 条触发，触发编辑器里**行为列表全空**，
而列表页的「条件 1 · 行为 3」看着是对的（那列走地图对拍，所以数字没问题）。

**根因**：`_split_tables()` 用「168 步长切分 + 段内类型必须全在已知表里」判定行为/事件表。
这张图里有一条**地图真值就是 609 的行为**：

```
[Actions] 01000105=2,14,0,8,…,A, 609,0,0,1,…,A
```

609 不在表里 ⇒ 校验不通过 ⇒ 整表退化成"全是事件" ⇒ **每条触发的行为数都变成 0**。

**改法**：对象类别改看 `obj+0` 的**类字**——`0x4F0EC392` = 行为（固定 168 B）、
`0x4F0EC393` = 事件（108/124 B）。24 档批量验证：所有对象非 392 即 393，
且与旧的步长切分结果 100% 重合 ⇒ 逐对象可读的硬事实。
类字不认识时才退回旧逻辑；未知类型**保留**（只提示，不再整表退化）。

同一条路径上还修掉一个：`_objects()` 的 `arg > 0xFFFFFF` 滤网会把
**参数 = -1（0xFFFFFFFF，引擎的"未设置"）** 的对象整条丢掉 ——
`SOV01UMD` 的 01000211 / 01000213 因此读出来"没有事件"。现在 -1 正常显示成
`（-1 = 未设置）`。

## 3. 修：「已执行」不再一律判成「等待中」

**症状**：`SOV01UMD.sav` 的 01000588「爱因斯坦」玩家确认**已经执行过**，工具显示"等待中"。

**根因**：`executed` 只有一条判据——**CellTag 节点消失**（§159/§168 基于"持久 1 + 摧毁法"得出）。
但那条路径只覆盖"挂载数减到 0 ⇒ 消费节点"这一种；**一次性触发跑完后引擎并不回收
CellTag / TagNode**，于是这类触发永远判不出"已执行"。

**新指纹**（该档 165 条触发里只有它一条符合）：

| 字段 | 01000588 | 其它在定时表里的触发 |
|---|---|---|
| CellTag 是否在「定时触发器挂接表」 | 是 | 是 |
| TagNode 帧数（`+0x50`） | **0（已减到零）** | 750 / 840 / 2100…（还没跑） |
| 重复类型 | 0 一次性 | 0 |
| 事件 | **8「任何事件」**（恒真） | 13 流逝时间 等 |

一次性 + 计时归零 ⇒ 轮询到第一帧就执行了，条目留在表里。
列表与编辑器现在显示「已执行（计时已归零）」，**橙字、不拦修改**
（`_is_executed` 仍要求"无节点"，避免误锁）。

## 4. 修：关联触发（一个标签共享给多条触发）

**背景**（玩家指出，FA2 的「关联触发」/ ra2map 教程）：
主触发挂着标签，从触发**把自己的标签删掉**，靠链子串起来，整条链共用那一个标签。

**存档字段（新定位，31 档验证）**：触发记录帧 `+132` = **下级（关联）触发的实例键**，`0` = 链尾。

```
SAVE5739.SAV：Player_Has_Plant8（唯一挂标签）
   └下级→ Plant7 → Plant6 → Plant5 → Plant4 → Plant3 → Plant2 → Plant1（链尾）
```

- SAVE5739：334 条触发里 202 条带链接、49 条链、251 条在链上，**0 处野值**；
- 交叉验证：`SOV01UMD` 的 `01000588 → 01000517`，与地图 `[Triggers]` 第 2 字段一致；
- 顺带确认：记录帧 `+128` 是**全档同一个常量**，不是标签键。

**顺带挖出第二个原因**：`trigger_repeat_type()` 只认「地图 `[Tags]`」或
「标签名 = 触发名 + 空格 + 数字」两种配对 ⇒ 名字不合规律、又没挂地图的档，
**整列"未读出（无标签）"**。现在先读**本条自己那个标签对象 `+0xB0`**（= 记录帧 `+120`），
不需要任何配对；从触发再沿链回退到链头。SAVE5739 的 **334/334 条全部读出**。

界面：
- 列表「触发类型」= `（共用）一次性·任一挂载`，「标签」列写"共用"；
- 编辑器状态行：`· 关联触发：共用「Player_Has_Plant8」的标签`；
- 改重复类型会先弹确认：**整组一起变**（写的是链头那个标签）。
- 标签/CellTag 相关字段（持久性、挂载数、执行状态）借链头；**事件/行为/TagNode 仍看本条**。

## 5. 修：触发名"打开一次就掉尾号"

**症状**：8 条 `Player_Has_Plant1..8`，在触发编辑器里**打开一次**，名字尾部数字就没了。

**根因**：`_on_name_change()` 里写死 `nm = nm[:16]`（按**字符**砍 16 个），
而它是**实时改名**（§257：输入即写盘）。`reload()` 回填名字会触发它 ⇒
`'Player_Has_Plant1'`（17 字符）→ `'Player_Has_Plant'` **直接写进存档**。
存档里触发名其实是 **52 字节的 GBK 字段**（上限 51 B），16 字符没有任何依据。

**改法**：去掉硬截断，改按 GBK 字节数校验（超了不写并提示）；
`set_trigger_name` 同步标签名时若「名 + 序号」超 51 B 就只写名字（避免写出半个汉字）。

**顺手修**：`_on_pick_trigger()` 原来只调 `self.reload()`，而 `reload()` 在 `sid=None` 时
用的是"上一条" ⇒ **下拉里切换触发根本不换人**（界面会弹回原来那条）。
另外刷兵用的触发名 `('刷%s%d' % ...)[:16]` 同样会把序号砍掉，改成按字节压缩、保留序号。

## 6. 修：列表文字显示不全 + 拖动条拖不动

**症状**：触发列表的长文本被切断，下面的横向滚动条怎么拖都没反应。

**根因**（三件事叠加）：

1. 列宽**写死**（合计 732 px）< 可视宽度 ⇒ 滚动条滑块占满整条，没内容可滚；
2. `ttk.Treeview` 的列默认 **`stretch=True`**：引擎会把列**按比例压到正好填满控件**
   ⇒ "总列宽永远等于可视宽度"，永不溢出 ⇒ **滚动条永远无效**，列还被压窄；
3. 单元格文本被**列宽**裁切——那是列内裁切，拖滚动条也看不到。

**改法**：新增 `ui/tree_fit.py`
- `autosize()`：按实测像素重算列宽（每列只量最长值，最多 400 行），并 **`stretch=False`**；
  总宽不足 ⇒ 余量分给名字/说明/状态；超出 ⇒ 先把"可让"列压到下限，仍超才横向滚动；
- `attach_tooltip()`：鼠标停在被裁的单元格上弹全文；
- `fit_on_resize()`：控件尺寸一变就防抖重算（首次填表时控件还没映射，量出来的宽度是 1）。
- 触发 / 事件 / 行为三页都接上。

## 7. 新：概览页「忽略全局AI」+ 一键切换

问的是「看看存档中能不能找到这个忽略全局AI」——**能找到**。

地图 `[Basic] IgnoreGlobalAITriggers`（FA2 面板中文就叫「忽略全局AI」）在存档里有一份镜像：
**明文 `0x34B4` 的 u32：0 = AI 触发生效，1 = 忽略（AI 触发不跑）**。

证据（三档交叉验证；A/B 两档前后各 64 字节完全一致、只差这一格）：

| 存档 | `0x34B4` | 对应地图 |
|---|---|---|
| `AI触发打开.SAV`（改图**之前**存的） | 0 | 当时 = no |
| `AI触发关闭.SAV`（改图之后存的） | 1 | `all01umd.map` = yes |
| `SOV01UMD.sav` | 0 | `sov01umd.map` = no |

> 这两档整档差 **20 万字节 / 4.6 万个差异段**、记录数 6 vs 7 —— 开关一改整局模拟全变，
> 直接对拍整档是找不出来的；方法是先取"前后 64 字节全同、只差 1 字节"的孤立差异，
> 再逐个排除单位/建筑/地形数据，最后与地图 `[Basic]` 交叉确认。

**用法**：概览页 →「地图与规则」卡片 →「忽略全局AI」一行，右侧「切换」按钮。
改的是**存档里**那 4 个字节（回主窗口「保存」才落盘），所以：
**已有存档不用回 FA2 改图重开**，直接在这里开关即可。

⚠ 语义仍建议游戏内验收（改这一格是否完全等效于改地图）：本版给了一份对照片
`AI触发打开_改忽略.SAV` 供 A/B 对照。
