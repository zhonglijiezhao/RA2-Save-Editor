# 关联触发（下级触发）说明

> 对应存档字段：**触发记录帧 `+132`**（u32，下级触发的实例键，`0` = 链尾）
> 对应地编字段：地图 `[Triggers]` 每行的**第 2 字段**
> 工具版本：v1.4.3 起可读，v1.4.4 起可改

---

## 1. 一句话

**关联触发 = 多条触发串成一条链，共用一个标签的挂接对象。**

地编（FA2）里叫「关联触发」，玩家口语里叫「下级触发」。它不是"执行顺序表"，而是**共享挂接对象**的手段。

## 2. 为什么需要它

**一个建筑（或一个单位）只能挂一个标签。**

想让同一栋楼"进去时做一件事、被摧毁时再做一件事"，就不能给这栋楼挂两个标签。做法是：

```
A（事件：进入建筑）  ──下级──▶  B（事件：被摧毁）
   ▲ 挂着标签，标签挂在那栋楼上          ▲ 标签不挂任何对象，靠链"继承"A 的挂接对象
```

于是 B 虽然自己没挂到楼，却能对"A 挂着的那栋楼"生效——这就是链存在的真正原因。

## 3. 存档里长什么样

链是**键链**：每条触发的记录帧里存一个 4 字节的**实例键**，指向它的下级；走到底为 `0`。

| 位置 | 含义 |
|---|---|
| 触发记录帧 `+132` | 下级触发的实例键（`0` = 链尾） |
| 地图 `[Triggers]` 第 2 字段 | 同一个值（地编的写法） |
| 标签对象 `+0xB4` | 反向指回"这条触发挂着这个标签" |

链头 = 真正挂着标签对象的那条（= 主触发）。**一条触发只被一条链指着**（实档里没有分叉）。

## 4. 两种合法写法（都对，别互相纠正）

### 写法 A：共用标签（FA2 标准做法）

链头挂标签，**从触发把自己那份标签删掉**，整条链共用链头那一个。

- 实测样本：`SAVE5739`，`Player_Has_Plant8 → Plant7 → … → Plant1`，只有 Plant8 有标签；
  334 条触发里"有标签 ∧ 有上级" = **0 条**。
- 代价：**从触发的重复类型、挂载数、执行状态全部属于链头那个标签**，
  所以工具里读这些字段时是"借链头"的，改重复类型也是**整组一起变**。

### 写法 B：各留标签 + 禁止自身（进阶做法）

**每条触发都保留自己的标签**、各自设重复类型，链只由 `+132` 串起来，
行为里加一条「**54 禁止触发 · 参数 = 自己**」收尾。

- 实测样本：`SAVE6443` + `all01umd.map`（AAAAAA / BBBBB / CCCCC，持久性 2 / 2 / 0，
  行为 19、16 后接 54，且 54 的参数指向自己）。
- 好处：不用删下级标签也能连链，从链尾往上删不影响前面（每条都能被自己的标签驱动）。

> ⚠ **「自己有标签 + 有上级」是正常形态，不是错误。**
> 旧版工具会把它误报成"共用别人的标签"，v1.4.3 起已修正。

## 5. 上级被禁用/删除，谁会被拖死

这是最容易搞错的地方，三轮修正后的最终口径：

| 本条（下级）的情况 | 结果 |
|---|---|
| 事件是**流逝时间 / 局部变量**这类（不需要挂接对象）**且有自己的标签** | **不受上级限制**——自己的标签 + 自己的计时器就够跑，链对它没意义 |
| 事件**要挂接对象**（进入 / 被摧毁 / 被攻击…） | 挂接对象来自**上级的标签** ⇒ 上级被禁用/删除就不触发 |
| **没有自己的标签**（写法 A 的从触发） | 无论什么事件，命都在链上 ⇒ 上游一停就没了 |

反过来：**从链尾往上删，不影响前面。**

工具里怎么体现：

- 触发页状态列会直接写 `上级已禁用·永不触发（<链路头 SID>）`——只在上表后两种情况下写；
- 编辑器状态行最前面加 `⚠ 上级 X 已禁用 ⇒ 本条永远不会触发`；
- 「禁用选中 / 软删 / 真删」之前会弹**连带名单**，只列真会死的那些，不吓人。

## 6. 工具里怎么看、怎么改

**触发页（列表）**

- 「触发类型」列对从触发显示 `（共用）一次性·任一挂载` 这种带括号的形式，「标签」列写"共用"；
- 说明书列写短标记 `共用「X」的标签`，完整解释看悬浮提示；
- **双击触发行** = 打开触发编辑器（启用/禁用改用**空格键**或按钮）。

**触发编辑器 →「下级触发」一行**

| 控件 | 行为 |
|---|---|
| 只读下拉 | 列出全档触发，`〔自己有标签〕` 会标出来；`（无 · 链尾）` = 断开 |
| **应用** | **只写记录帧 `+132` 这 4 个字节**。不增删对象、不动序号、长度不变 ⇒ 随时能改回来 |
| **跳到下级 →** | 顺着链往下走，不用在下拉里翻 |
| 位置提示 | `上级 X · 下级 Y · 这条链共 N 条，本条第 i 条（链头 … 链尾）` |

**安全阀**

- **成环 / 自指**直接拒绝（引擎沿 `+132` 走链，环会让它转不出去）；
- 目标**已有另一条链指着**（分叉，实档 0 例）先弹确认；
- 目标**自己有标签**时只提醒、不拦——这是写法 B，合法；
- **新建 / 复制触发不再继承模板的链接**（以前克隆模板会把别人家的下级一起抄过来）；
- **删除触发自动摘链**：`A→B→C` 删 B ⇒ 自动变成 `A→C`，不留指不到任何触发的野键。

**相关：行为 53 / 54 / 12 / 22**

「允许触发 / 禁止触发 / 摧毁触发 / 强制触发」的参数是**另一条触发**，
存在行为对象 **`+100`**（不是通用参数槽 `+72`）。参数列现在显示目标触发 ID，
含义列写 `01000004 CCCCC（自己）`，改的时候写的也是这一格。

## 7. 已知边界

- **不能新建/删除标签对象**：想让一条本来有标签的触发退回"纯从触发"（写法 A），
  还得去地编侧删标签。
- **插到链中间要两步**：`A.下级 = X`、`X.下级 = B`，还没有一步式的"插到…之后"。
- 触发页列表没有独立的"链"列，链关系在编辑器里看。

## 8. 排查清单

存档改完进游戏不对，按这个顺序过一遍：

1. **链头还在吗？** 链头被禁用（TagNode `+88` = 0）⇒ 后面整串按上表判断能不能跑。
2. **从触发该有标签吗？** 写法 A ⇒ 没有；写法 B ⇒ 有，且各设了重复类型。
3. **重复类型（标签持久性）对不对？** 0 一次性·任一挂载 / 1 一次性·挂载清空 / 2 可重复。
   从触发的这份是链头的，改它等于改整组。
4. **写法 B 忘了「54 禁止触发·参数=自己」** ⇒ 可重复的触发会一直重复，收不住尾。
5. **链有没有断？** 记录帧 `+132` 为 0 就是链尾；误清成 0 会让下级失去上级。
6. **不要在存档侧找地编的"关联触发勾选框"**——那是地编的界面概念，
   存档里只有 `+132` 这一个键。
