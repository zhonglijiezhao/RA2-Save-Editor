## 已知事实（这些是上面两阶段的依据）

- 建筑记录 **1860B** = `[16 GUID][4 键][1840 对象体]`；`base = 记录 + 0x14`
- **476B anim 对象**：`[count u32][476 × count]` 连续分组，count 在首条 −4；
  建筑 → anim 指针在 **`+0x57C`**；anim 内部键组 = `K` / `K+0x70` / `K+0x90`
- ★建造态真值（§196 定案）：
  · **「刚放下」= `AC=-1 / BC=0 / D0=建造总帧 / 10C=0 / 534=1 / 6E4=0`** ⇒ 引擎读档后**自己播一遍、自己建子对象** ⇒ 完整；

  · 动画进度不落盘（写不出"播到一半"）
- 电力：`House+0x53B8` 只是快照；引擎按建筑 `534/6E4` 重算

## 🚧 下一步（按价值排序）

### 1. 事件 / 行为「列表化编辑器」— **排序与删除已完成（§193 / p140），新增待做**

现状：**上下移 + 单条删除已可用**（事件页/行为页各三个按钮，`_selftest_ev193.py` 24/0）。
剩余：**新增/插入**（要插字节 + 分配新键），以及修 `add_action()` 在 7MB 小档上静默无效的问题。

已探明的结构差异（这决定了两条路线的难度完全不同）：

| | 存储方式 | 排序怎么做 | 风险 |
|---|---|---|---|
| **事件** | **键链**：触发实例 `+192` = 链头键，每个事件 `+0x3C` = 下一个键 | 纯改指针（4 字节 × N），**长度不变** | 低 |
| **行为** | **连续数组**：一段连续对象，`+0x38` = 序号 | 需要交换对象内容（不能整体搬，`+0x10` 存自身键） | 中 |

下一步具体动作：
1. `move_event(sid, index, delta)`：链序交换 + 写回链头与各 `next`（**零长度改动，最安全**）
2. 事件表加「链序」列（否则改完顺序界面上看不出来，用户会以为没生效）
3. 违反铁律要拦：**含事件 13（流逝时间）时不允许把它从第一位移走**（§175：36/37 只有第一位的事件 13 才算心跳）
4. 行为排序：先做「交换两条行为的参数（类型/参数/路径点/建筑名）」，保留各自键
5. **删除**事件/行为：要从明文里切掉 108B/168B 并递减组计数、重连前后键 ——
   会改动明文长度，必须走完整的重压 + 全档偏移重算，建议最后做，并且**每档必进游戏验收**
