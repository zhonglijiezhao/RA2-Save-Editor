> 样本：玩家同一局内 `E:\YURI\原存档.SAV`（11 栋 / 16 伴随）→ **卖掉空指部 GAAIRC @(72,54)**
> （组内**最后一栋**、1872B 长记录、**3 个伴随**）→ `E:\YURI\卖掉空指部.SAV`（10 栋 / 13 伴随）。

## 1. 结论（一句话）

**引擎删建筑的做法和我们 `remove_building` 做的完全一样**：删整条记录 + 组计数 −1 +
**删掉它的伴随对象** + 每张登记表剔键 + 清格子（键与 格−8 / 格+0x1C 标志位）。
**唯一多出来的动作 = 引擎额外新建了 1 个对象**（见 §3）。

⇒ **RM1/RM2/RM3 弹框的原因不在"删伴随"**。旧结论「引擎不删伴随」被推翻。

## 3. 唯一差异：引擎额外新建的对象

- **类 GUID `c42d270e-0f9c-11d1-b709-00a024ddafd1`**（= `0x0E272DC4`）。
  同族：伴随 `c32d270e`(C3)、建筑记录 `c62d270e`(C6)。**旧存档里这个类一个实例都没有**。
- **键 `0x136a2808`**（落在 `0x13xxxxxx` = 引擎运行期新建池）；**实例 ID `0x000FA386`**
  （= 本档现有最大 +0xE，顺延分配，和 `+20` 同一个计数器）。
- 记录布局与建筑记录同构：`[GUID][键][4 个类常量指针][0x000FA386][…]`。
- **被写进 27 处**：表0、表1 各 1 处；**12 个所属方记录**各 1~2 处（同一键共享）；
  自记录 1 处（位于建筑**类型名数组**（`d9338bae` 记录、"GAPOWR"/"Allied Power Plant" 名字区）之前）。
- **大小 ≈ 1909 字节**（由长度账反推）。
- 其它并存档（`开局档.sav` / `开局存档.sav` / `OK1` / `能建光棱塔` …）里 **0 次**；
  只有"卖过建筑"的这份样本里有 1 次。⇒ 高度怀疑是**卖建筑时产生的持久对象**（身份未定：
  可能是残骸 / 被拆建筑的 limbo 实例 / 引擎的一个已知小泄漏）。
- **我方不建它，也不会造成悬空引用**（没有它就没有任何字段指向它 ⇒ 加载器的 A ⊆ B 依然成立）
  ⇒ **理论上不影响加载**，但**必须在游戏里确认**。

## 4. RM1/RM2/RM3 弹框的真因：还没定案，且旧对照有混淆

- 旧对照全部用 `OK1_光棱塔_远处空地.SAV` 当母本 —— 它**含工具注入的 ATESLA**（非原生对象）。
- 四个结果里**唯一成功的是 RM4 = 删掉那栋注入物本身**；RM1/RM2/RM3 都是"删原生建筑、留着注入物"。
- 所以现在有两个可疑变量，必须用**干净母本**做单变量：
  ① 被删建筑在组内的**位置**（RM1/RM2/RM3 都不是末位，RM4 是末位；引擎样本也是末位）；
  ② 母本里是否**残留工具注入对象**。
