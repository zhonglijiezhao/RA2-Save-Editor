# v1.2.4 — 任务名改成「以 ra2md.csf 为准」（地图文件名就是 CSF 键）

这一版解决的是「概览页那行任务名到底读自哪里」。以前它是**猜**的，猜错了；现在按你给的规则读 CSF。

## 1. 以前为什么是错的

旧实现把文件头 16KB 按 UTF-16 的**两种对齐**都解一遍，挑"最长的含中文串"。结果：

- 挑到的是 **`0x1450` 的任务简报**（"辽阔平原之上，钢铁洪流列阵开战……"），不是名字；
- 奇数字节对齐解出来的乱码串往往更长，于是那一行显示成 **`鈀辽阔平原之上…`**（首字是错位产物）。

## 2. 现在的规则（你给的"百分百正确"法）

> 地图名是 `ALL01UMD` → `ra2md.csf` 里的 `all01md` 就是任务名。

实现后的实测：

| 地图文件 | 命中的键 | 值 | 短名 |
|---|---|---|---|
| `ALL01UMD.MAP` | `name:all01md` | **军事行动：铁峰征讨三绿野孤城** | 铁峰征讨三绿野孤城（`name:all01mdsav`） |
| `SOV01UMD.MAP` | `name:sov01md` | **军事行动：时空转移** | 苏联 01 - 时空转移 |
| `ALL01MD.MAP` | `name:all01md` | 同第一行 | 同第一行 |

换算：`ALL01UMD → all01md` 是把末尾 **`umd` 换成 `md`**（不是去掉最后一个字符）。

**两条独立来源互证**：CSF 里的值与存档 `0x1360` 里存的值**完全一致** —— 说明游戏保存时就是把 CSF 解析结果写进了存档。所以优先级是：

```
有地图 → 以 CSF 为准        （你这条规则，最准）
没地图 → 用存档 0x1360      （游戏自己存的那份，仍然可信）
两者都没有 → 旧的启发式兜底（并且修掉了乱码首字）
```

概览页还会多显示一行「任务副标题」，以及内部记录 `任务名来源`（`CSF：name:all01md` / `存档 0x1360`），你一眼能看出这个名字是怎么来的。

## 3. 顺带把 CSF 格式摸清了（和网上写的标准不一样）

```
头 24 字节：magic ' FSC' | version | nLabels | nValues | 8 字节 0
每条 label：' LBL' | nPairs | keyLen(u32) | key[ASCII，不补 0]
每个 value：' RTS' | len（**字符数**）| 数据（len×2 字节）
```

而且 **值是「逐字节取反的 UTF-16LE」**：`theme:intro` 存的是 `b6 ff b1 ff ab ff ad ff b0 ff`，逐字节取反后正好是 `INTRO`。按普通 UTF-16LE 直接解会得到一堆半角假名乱码。新模块 `core/csf.py` 三种解法都试、按"像人话"打分取最优。

新增能力（`core/csf.py`）：解析、大小写不敏感查询、按文件指纹缓存、`ra2md.csf` 自动定位（地图目录 → 存档目录 → 上两级）。

## 4. 一条反例（写进注释，防止以后又踩）

`B0_光棱塔同类型_带格子.SAV` 里 `0x13BA` 写的是 `Name:ALL01md`，但它自己的 `0x1360` 是「军事行动：丛林救援」——两者矛盾。所以**拿存档里那个 ASCII 名字键去查 CSF 会查错**，没地图时就老实回退 `0x1360`，不猜。

- `_selftest_ev276.py` **24/0**：四个字段偏移、名字不是简报、无 `鈀`、兜底路径也干净（★兜底原来读的是**容器原始字节**，对齐和明文不同，仍会出乱码，已改成读明文）。
