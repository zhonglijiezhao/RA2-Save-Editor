## 地图对照（事件/行为 → 归属触发）

存档里**没有**「哪个触发挂哪些事件/行为」这个字段，但**地图文件有**：
`.map` 的 `[Events]` / `[Actions]` 段**以触发ID 为键**。所以打开存档时会：

1. 在存档目录（含一层子目录）与游戏目录里找 `*.map` / `*.yrm`；
2. 用**触发ID 集合**筛候选（要求重叠度 ≥ 60%，且按**较大一侧**算 —— 否则只含 1 个触发的小图会被误认为完全匹配）；
3. 把地图的条件/行为**按顺序摊到存档的数组上**，逐项对拍：

| 对拍结果 | 含义 | 界面表现 |
|---|---|---|
| **地图对照一致 ✓** | 数量与数值都对上 | 事件/行为页显示完整「所属触发」，触发页显示「条件 N · 行为 M」 |
| 地图部分对照 | 数量对不上（如事件 存档 2 / 地图 4） | **不给归属**，只读提示；说明该地图很可能是**另一个版本** |
| 结构相符（数值有差异） | 数量对上了但某些值不同 | 照常给归属，并标注 ⚠（通常是你在存档里改过） |
| 未挂地图 | 没有候选或重叠不足 | 归属列显示 `—`，可按顺序对照地编 |

★ 判定"该地图是不是这一档的"，**触发ID 集合是最可靠的钥匙**；数值对拍用来区分同一地图的**不同版本**。

### 所属方金钱是怎么定位的

**关键：不要用「阵营记录起点 + 固定偏移」**（那条路只对当前玩家成立，2026-10-13 已证伪）。
真正的结构是**「经济结构」块**，排列严格等距（步长 90836 字节，顺序 = `[Countries]` 注册序）：

```
[60 字节固定模板]  99 99 f9 3f 00 00 00 40 33 33 f3 3f 00 00 00 a0
                   99 99 e9 3f 00 00 00 00 00 00 f0 3f 20 85 eb 51
                   e1 7a f4 3f 00 00 00 40 e1 7a 94 3f 00 00 00 e0
                   51 b8 9e 3f 05 00 00 00 0a 00 00 00
[阵营位掩码 u32]   1 << 在 [Countries] 里的注册序（美国=1、韩国=2、苏俄=256、尤里=512 …）
[金钱 u24]         该阵营的资金
                     ↓ +304 字节处还有一份完全相同的副本
```

定位算法：全文搜那 60 字节模板 → 读紧跟的位掩码 → 用 `bit_length()-1` 反推阵营 → 取其后 u24。
**当前玩家**额外走它自己的镜像字段（并写主字段）。

已确认字段汇总（相对「阵营记录起点」，仅供参考，代码里用模板法）：

| 偏移 | 含义 | 证据 |
|---|---|---|
| `+144` | 地图 Credits（1~12，×100 = 游戏内金钱） | `Russians+144=8`、`YuriCountry+144=9` 与 `all01umd.map` 完全吻合 |
| `+7708` | **仅当前玩家**的金钱镜像 | 改 → 存 → 读档生效 |

**验证方式**（这是本次定位成功的关键）：在地编里把各阵营的 `金钱(x100)` 改成**七位数的独特值**
（如韩国 4879 → 487900、苏俄 7896 → 789600、尤里 8935 → 893500），**重开新档并立刻存档**，
再用这些独特值在明文里反查 —— 命中位置一一对应，且旧档里同一位置读出的正是旧地图值。

## 「流逝时间」为什么"改了没生效"（2026-10-13 破解）

**症状**：把事件 `13 流逝时间` 的参数从 60 改成 10，另存读档后仍在 **60 秒**触发。

**原因：同一个等待时间在存档里存了**两份**——

| 位置 | 含义 | 谁在用 |
|---|---|---|
| 事件对象 `+72`（u32） | **秒**（= 地图 INI `[Events]` 里写的值） | 只作副本/展示 |
| 触发记录里 `C4 60 72 00` 标记**之后**的 u32 | **帧** = 秒 × 15（游戏逻辑 **15 帧/秒**） | ★ **引擎按它计时** |

标记 `C4 60 72 00` 是游戏数据段里的一个**静态指针常量**，在同一对象里位置稳定，
所以能当锚点（它前面的内容长度随档变化，**不能写死偏移**）。

**证据**

| 观察 | 结果 |
|---|---|
| 只改事件 60→10 | 游戏仍 60 秒触发（**改动被忽略**）❌ |
| 同时改标记处 900→150 | 见下方验证档（双写，全文只差 3 字节） |
| 跨档核对标记处 ÷15 | 13/60→**900**、13/5→**75**、13/20→**300**、13/4789→**71835**、13/1337→**20055** —— 全部等于某个事件的秒数 ✓ |

**终验（2026-10-13）**：双写档（事件 60→10 且帧 900→150）读档后**约 10 秒显示全图** ✓ —— 端到端闭环。

**工具已处理**：编辑 `13 流逝时间` 时**自动同时写**帧数字段；
若找不到匹配的帧数块（例如多触发档里该触发没有这个块），会**弹窗明确警告**"只改了秒数，
等待时间可能仍是原值"，绝不假装成功。

## 事件 / 行为是怎么定位的（2026-10-13 重做）

**⚠ 先说被证伪的旧做法**：曾用「`[类型][0][参数]` 三元组 + 固定步长（事件 108 / 行为 168）拼连续链」。
这在 `ALL01UMD.sav` 上碰巧对，但在别的档上会锁定到**巧合链**（明文里有 10 万+ 条候选），
把**浮点数组**当成事件表，显示成「类型 63/64/72」这类垃圾值，于是"改了不生效"。
**该实现已整体删除。**

**现在的判据（确定性，不猜）**：每个事件/行为对象的体内含一段 **16 字节恒定签名**
（跨档稳定；58 个存档批量验证 **100% 命中**）：

```
obj+0   4F0EC392 / 4F0EC393     ← 随对象微变
obj+4   11D20A55
obj+8   6000A7AC
obj+12  B55B0508
```

对象布局：**类型在 obj+64、参数在 obj+72**（界面显示的「明文位置」就是 obj+64）。

数组结构 —— `[行为对象…] [4 字节] [事件对象…]` 连续存放：

| | 对象尺寸 | 说明 |
|---|---|---|
| 行为 | **固定 168 字节** | 用 168 的连续性即可认出行为段 |
| 事件 | **随档变化（实测 108 / 124）** | ⇒ **绝不能用固定步长**（旧实现正是死在这里） |

切分规则：对象按偏移排序后，**第一个 Δ≠168 处就是「行为段 → 事件段」的分界**
（实测分界 Δ=172 = 168 + 4 字节间隙）。切完再做一次**类型空间校验**
（行为段类型须全在 `[ActionsRA2]`、事件段须全在 `[EventsRA2]`），不通过就只读、不提供修改。

**验证对照**（`all01umd.map` 的 `[Events]`/`[Actions]` 段就是权威真值）：

| 存档 | 工具读出 | 判定 |
|---|---|---|
| `ALL01UMD.sav` | 行为 `16 显示全地图 / 6 全部寻敌`，事件 `13/179 12/7965 11/2 13/7989` | ✅ 与地图真值逐条一致；且这 4 个事件元组在 10MB 明文里**各自唯一命中** |
| `SAVE6784.SAV` | `13/179, 13/4789` | ✅ 与你在地编里设的值一致 |
| 58 个存档 | 类型空间全部合法、低置信 0 个 | ✅ |

## 自检（改完源码必跑这一步）

**唯一入口**：`py _selftest_all.py`（★2026-10-28 审查 P4-18）

以前 140+ 个 `_selftest_*.py` / `_ui_ev*.py` 全靠人肉记「跑哪个、基线是几比几」，
交接文档每次都要抄一遍数字 —— 那本身就是该自动化的信号。

```
py _selftest_all.py                 跑全部，和基线比（发布前跑这个）
py _selftest_all.py --fast          跳过最慢的几个（unit_place / ai / ev280）
py _selftest_all.py --only ev29     只跑名字含 ev29 的
py _selftest_all.py --list          只列清单
py _selftest_all.py --update        把当前结果写成新基线
py _selftest_all.py --timeout 120   单个用例超时（默认 300 秒）
```

判定口径（**只认"相对基线的退化"**）：

| 情况 | 算不算失败 |
|---|---|
| 基线是绿的，这次变红 / 报错 / 超时 | ✅ 失败（退出码 1） |
| 基线是绿的，这次通过数变少（断言被删） | ✅ 失败 |
| 基线本来就是红的（老用例 / 环境缺样本） | ❌ 不算 —— 否则门禁永远红，没人看 |
| 新加的用例（基线里还没有） | 只提示，`--update` 后入基线 |

基线文件 `_selftest_baseline.json` **跟着仓库走**（.gitignore 里专门开了白名单）：
它是"改完有没有退化"的唯一判据，不能只留本地。

> 加新用例的姿势：写 `_selftest_evNNN_xxx.py` → 跑一次 `--only evNNN` 确认全绿 →
> `--update` 入基线 → 提交。**先确认绿再入基线**，别把红的写进基线（那就等于把坑钉死了）。

## 安全设计

- **默认另存为新文件**，绝不覆盖原档；「原地保存」会先把原档备份到 `_备份存档\` 子目录（备份文件名含原存档名，**注意该目录不要放进游戏存档目录**，否则可能被读档列表枚举）。
- 触发切换**只写「触发类 GUID 前 8 字节」那 1 个字节**，写入前先校验该处确实是 0/1（否则判定未定位、只读并拒绝写入），因此不会碰到记录里的其它数据。
- 每次保存都做**双重自证**：重建后重新解码整份存档，明文必须与内存中的明文逐字节一致，否则拒绝写盘。

## 已知限制

- **大型自制任务档（明文 37.4MB / 599 块级别）**：这类档的对象数组与普通档不同 ——
  「触发/标签 定义」是独立数组（等距 232，类 GUID `61DE341E-…`，+120 字节 01=触发 / 00=标签），
  经济块的 60B 模板会被 mod 的**每阵营 AI 参数**改掉 ⇒ 只能定位一部分所属方的金钱。
  已做：① 定义数组记录正确分类（不再显示"未识别结构"）；② 金钱块的 **+304 第二副本改为
  "验证一致才写"**（这类档没有该副本，盲写会改坏数据）；③ 概览显示「经济块 N/12」。
  **已解决（2026-10-14 独特值实验定案）**：经济块定位改为三级 ——
  ① 60B 模板扫描（普通档）；② 锚点 `51 B8 9E 3F 05 00 00 00` + 金钱@+16（u32≤0xFFFFFF），
  按注册序指派（11 块=Alliance..Special，10 块=Alliance..Neutral）；
  ③ 尾部兜底（Special 的块模板是变体）：金钱∈(0,0xFFFFFF] 且 +304 副本相同
  且 **money-12..-9 == `05 00 00 00`**。
  验证：老档 12/12 不回归；独特值档 **8/8 全对**；大任务默认档 11/12（Special 默认 0，诚实跳过）。
  ⚠ 触发数量与地图对不上是**正常现象**：开局即执行的触发完成后会**自毁**，存档里就没有了。
- 旧图（C*/T*/Z* 记录布局）的触发**运行态字节位置尚未定位** → 该图触发只能只读查看（定义状态可正确显示）。

- **⚠ 不要把事件/行为类型设成 0「-无事件-」/「-无行为-」**：地编里它是占位项（原文「空事件，没作用」），
  写成它没有任何用处、只会冒险（实测带 0 的档读档直接弹 `internal error`）。
  工具已设防：写入被拒绝、下拉框里没有 0 号项、已存在的 0 行标红并弹告警。
  **要取消一个条件/行为，请在地图里删掉它**（存档里对象数组长度固定，删不掉），
  或改成永不满足的条件（如「13 流逝时间」+ 极大秒数）。
- **触发启用位的定位依赖那条恒定「类 GUID」**；若某档里找不到它、或 GUID 前 8 字节不是 0/1，
  工具判定**未定位**并**拒绝修改**（宁可不给，也不乱写）。
- **「启用 / 禁用」在游戏里到底有没有用**：已验证（成对档只差 1 字节，游戏内表现不同）；
  但**不是所有触发都能改** —— 定位不到的记录只能去地编改图后重开新局。
- **等效禁用（备用手段）**：把该触发的事件条件改成永不满足（`13 流逝时间` + 极大秒数）。
  只对"可改成永不满足"的条件有效（「任何事件」这类不行），因此只是**兜底**，不是通用方案。
- ★ 两条方法论：**游戏内实测前必须清空游戏树（含所有子目录）下的存档**；
  **优先找"成对档"做 diff**（比盲试快一个数量级）。

- **事件 / 行为本身不带归属**：存档里没有"每个触发挂几个事件/行为"的字段（两条触发记录逐字节 diff 过，差异全是堆指针残留）。
  **挂上地图后即可显示归属**（见「地图对照」一节）；没挂地图时按顺序平铺，对照地编确认。
- **事件/行为的定位依赖那 16 字节对象签名**；若某个存档里签名不同（例如换用别的平台/大改过的引擎），
  工具会判为"未定位"并拒绝修改（宁可不给，也不乱给）。遇到请把它发来，加一条签名即可。
- 定位已不再依赖 464 字节记录数组（改用「经济结构模板」），所以早前那类"没有 464 数组"的存档（如官方任务第一关）现在同样可用。
- 本工具的 LZO 重编码器比原游戏弱：被改动的 64KB 块压缩后可能略微膨胀。CFB 空间不足时会在**文件尾部追加扇区并同步扩展 FAT**（已实现并验证），因此文件可能比原档稍大，属正常现象。
- 各阵营金额上限同为 16,777,215（u24）。
- 单块（64KB）重编码约 1 秒；改 1~3 处 ≈ 3~5 秒，改很多处会明显变慢（界面有进度提示）。
- 金钱上限 16,777,215（u24 限制）。

## 文件说明

```
RA2存档编辑器/
  RA2存档编辑器.py      主程序（tkinter GUI）
  launcher.py           ASCII 启动入口（转调主程序 + 崩溃日志 + --selftest 自检）
  启动.bat              启动器（纯 ASCII + CRLF）
  启动(调试).bat         前台调试启动器（出错信息可见）
  core/
    editor_core.py      业务层：打开/解码/记录扫描/改金钱/改触发/事件/行为/地图对照/保存
    map_ini.py          地图 INI 解析（[Triggers]/[Events]/[Actions]/[Tags]，权威真值 + 归属）
    fa2_tables.py       地编编号表（由 FAData.ini 生成，供下拉框用）
    cfb.py              CFB 复合文档解析
    lzo1x.py            LZO1X 解码器（内核实现移植，双基准验证）
    lzo_compress.py     LZO1X 贪心压缩器（155/155 块往返通过）
    cfb_surgery.py      CFB 流内手术（长度变化时重建 FAT/目录项）
```

命令行也能用（无需 GUI）：

```bat
D:\py\python.exe core\..\RA2存档编辑器.py     :: GUI
:: 或直接用核心层
D:\py\python.exe -c "import sys;sys.path.insert(0,'core');from editor_core import SaveDoc;d=SaveDoc(r'存档.sav');print(d.info);d.set_money(100000);d.save(r'输出.sav')"
```
