## 1. 新：概览页「存档修复 · 空气墙」

概览页最下面多了一张卡片，两个按钮：

| 按钮 | 作用 |
|---|---|
| **检查** | 只扫描、不改任何字节，弹窗列出命中的坐标（前 16 个） |
| **一键清除** | 直接修掉，清完提示保存 |

**它修的是什么**：格子上明明空无一物，却仍然登记着"被占用"。
载具寻路读这个标记 → 认为过不去；步兵不读 → 照常走。
所以症状永远是**只挡载具、步兵没事**。

来源不止一种：超时空传送、铁幕、时空兵下车、单位被吸收……走的时候漏了清，格子就
永远立着一块看不见的墙。

### 判据（两个字段必须同时满足）

| 偏移 | 含义 | 空气墙时 |
|---|---|---|
| `+0xF8` | 占用对象键（0 = 无主） | **0** |
| `+0x138` | 占用标记，**只有最低 1 字节** | **0x04 / 0x08 / 0x10 / 0x20** |

位含义：`0x01..0x0F` 步兵 / `0x10` 树石 / `0x20` 载具 / `0x80` 建筑。

### 为什么只清那 1 个字节

引擎里格子的拷贝函数（`gamemd.exe` 的 `0x566066` / `0x566878`）是

```asm
mov dl, byte ptr [esi+0x138]
mov byte ptr [edi+0x138], dl     ; 只搬 1 个字节
```

说明上面 3 个字节属于别的属性。有些格子的 `+0x138` 显示成两亿量级的大数
（如 `0x0D6E0000`），其实**低字节是 `0x00` —— 根本不是空气墙**。
整 4 字节清零会把旁边那些属性一起抹掉，所以这里严格只写 1 个字节。

### ★ 清除后要「保存 + 读档」才生效

这一点反直觉，但实测反复确认过：**改存档有效、改内存无效**。

```
读档开始 → 格子字段读入 → [引擎按 +0x138 重建通行状态] → 进入地图
                                  ↑
                    只有这一刻之前改才有用
```

整个 `gamemd.exe` 里**搜不到任何一条 `test [reg+0x138]`** —— 通行判定不实时读它，
只在读档那一刻消费一次。所以游戏中途改内存里的这个字段，无论清多少格都白费。

### 实测

| 存档 | 格槽 | 检出 | 掩码 | 位置 |
|---|---|---|---|---|
| `SAVE2CD6.SAV`（超时空+铁幕） | 12720 | 9 格 | `0x20` | (77,82)~(79,84) 连续 3×3 |
| `SAVE72AE.SAV` | 12720 | 5 格 | `0x04`/`0x08` | (76,82)~(76,84)、(83,84)(83,85) |

清完保存、进游戏读档，玩家确认空气墙消失。逐字节比对：全文只差那 9 / 5 个字节，
明文长度完全不变。

## 2. 顺带：三个命令行工具

`app_main.py` 加了 headless 子命令，方便批量处理：

```bat
REM 看/改「这栋楼是不是工程师占领来的」（b 帧 +0x6AF）
app_main.py --captured 存档.SAV --all
app_main.py --captured 存档.SAV --type GAPOWR --set 0 --out 新档.SAV

REM 抛射体的分裂配置（Cluster / ShrapnelWeapon / ShrapnelCount）
app_main.py --shrapnel 存档.SAV --set NZ2BOUNCE=8 --out 新档.SAV

REM 两级自我折射电弧链
app_main.py --refract 存档.SAV --n1 3 --n2 1 --term ElectricBolt --out 新档.SAV
```

其中 `--captured` 背后是一个引擎硬规则：**工程师占领来的建筑，引擎写死禁用工程师
残兵**（Ares 的 `Crew.EngineerChance` 压不过它）。把 `+0x6AF` 清成 0，建造场被拆
之后立刻恢复出工程师。

之前保存的档照常能读。
