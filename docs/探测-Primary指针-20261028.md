# 探测报告：TechnoType 的武器槽位（Primary 指针）

> 一轮**只探测、不写入**的会话产出。目标：回答「能不能给某个兵换把枪」。
> 结论：**能定位到字段，也能读出当前值；能不能安全写入还没验证（见 §5）**。
> 所有结论都用 `_probe_primary.py` 固化成了断言（23 条，全绿），改代码前后可以直接跑。

---

## §1 一句话结论

存档里的每个类型对象（步兵/车辆/飞机/建筑）都有四个 4 字节槽位，存的是
**指向 WeaponType 对象的裸指针**（不是名字、不是序号）：

```
X = 「Name:」出现位置 − 0x19       ← 对象起点锚点（456 个对象全中）
X + 0x874   Primary
X + 0x890   Secondary
X + 0xA70   ElitePrimary
X + 0xA8C   EliteSecondary
```

**换枪 = 把某个槽位的指针改成"另一把武器的指针"。** 难点不在改，在**从哪儿拿到那个指针**
（§4）和**改了到底生不生效**（§5）。

## §2 怎么找到的（过程值得留档）

### 2.1 第一堵墙：这些对象根本扫不到

上一段的 `_type_objects()` 靠"双名特征"（`X` 和 `X+0x40` 是同一份名字）扫出 1193 个
Type 对象，覆盖武器/弹头/动画…，**但扫不到步兵/车辆/建筑的类型**——
它们的布局是 `X+0x00 = ID（E1）`、`X+0x40 = Name（GI）`，**两份内容不同**，
所以"内容相同"的判据天然失效。

改从原始字节下手：搜 `Name:XXX` 串（引擎把 UIName 存成 `Name:E1` 这种形态），
456 个能在 rulesmd.ini 找到同名节，锚点 `X = 命中点 − 0x19`。

**锚点校验**：`Strength` 在 `X+0x7C`，**333/338 命中**（96%）；
`Cost` 在 `X+0x5EC`。不匹配的 5 个（AMBU/SHK/CAHSE04/PDPLANE/BPLN）应该是地图 INI 覆盖
或重复对象取错了份。⇒ 锚点可靠。

### 2.2 第二堵墙：三次错误的猜测

| 猜测 | 检验方式 | 结果 |
|---|---|---|
| 武器以**字符串**存在对象里 | 在 E1 对象区搜 `M60`/`Para` | 0 次 ⇒ 否 |
| 武器是**序号**（第几把武器） | 4/2/1 字节 × 全对象范围，比 0 基/1 基/全局对象序号/掩码 | 全部 < 50% ⇒ 否 |
| 武器是**存档内偏移** | 找落在武器表区（0x19B1AD7~0x19C6F73）的值 | 0 个 ⇒ 否 |

其中踩过两个陷阱，记下来免得下次重犯：

1. **纯度法要先排除常量**。第一版判据是"同一把武器的对象在该偏移值相同"，
   结果全 0 和全常量天然 100% 命中，前 25 个候选全是垃圾。
   必须同时要求"不同武器必须不同值"。
2. **不能把四类混在一起扫**。InfantryTypeClass / UnitTypeClass / BuildingTypeClass
   布局不同，同一个偏移意义不同。第一版混扫时"同 Primary 同值"永远凑不齐，
   差点误判成"存档里根本没有武器字段"。

### 2.3 破局：Spearman 相关 + 类别分开

按 `[InfantryTypes]`/`[VehicleTypes]`/`[BuildingTypes]` 分类后，算每个偏移值与
"武器在武器表里的序号"的 Spearman 相关。步兵类 `+0xDD4` 给出 r=0.98 ——
**这是假阳性**（那是对象自己在类数组里的序号，天然与顺序相关，等于没找到）。

真正的线索来自"**同值必须同武器**"的严格版：`+0x874` 上 354 个对象里
71 个不同值、**71 个全部一致、冲突 0**。这时才注意到这些值都是
`0x0C131E90` 这种**大数**——是进程地址，不是序号。

## §3 证据数据（`E:/YURI/SAVE0665_修改.SAV`）

### 3.1 四个槽位的双向唯一性

| 槽位 | 偏移 | 覆盖武器 | 一指针多武器 | 一武器多指针 |
|---|---|---|---|---|
| Primary | +0x874 | 69 | **0** | 4 |
| Secondary | +0x890 | 25 | **0** | 0 |
| ElitePrimary | +0xA70 | 39 | **0** | 1 |
| EliteSecondary | +0xA8C | 9 | **0** | 0 |

"一指针多武器 = 0"是最硬的证据：**没有任何两个不同武器共用同一个值**。
"一武器多指针"的少数几例，全部来自**同名类型对象有多份**（§3.3）。

### 3.2 抽样

| 类型 | rules | 存档里的四个值 |
|---|---|---|
| E1 | M60 / Para / M60E / ParaE | `0C131E90` `0C136E10` `0C146060` `0C144090` |
| E2 | M1Carbine / - / M1CarbineE / - | `0C143CD0` `00000000` `0C140840` `00000000` |
| HTNK | 120mm / - / 120mmE / - | `109E9D40` `00000000` `109EAE90` `00000000` |
| DESO | RadBeamWeapon / RadEruptionWeapon / RadBeamWeaponE / - | `0C16FE90` `0BAEDE90` `0BAB3E90` `00000000` |
| ATESLA（建筑） | PrismShot / PrismSupport / - / - | `109612C0` `10966850` `00000000` `00000000` |
| GAPOWR（无武器） | - | `00000000` `00000000` `00000000` `00000000` |

⇒ 空槽是 0；**建筑和步兵用同一套偏移**（ATESLA 与上面几个同位对齐）。

### 3.3 同名对象有多份（**写入时必须考虑**）

456 个对象 / 354 个唯一名：37 个名字出现 2 次、15 个出现 3 次以上（CAR 5 份、DOG 4 份）。
多数副本的指针相同（CARRIER / DRED / SMIN / ENGINEER），但有几个不同：

```
DISK    x2   DiskLaser       0xc0e7090 vs 0xc11e630   ← 两个不同指针
DOG     x4   BadTeeth        0xbab1e90 / 0xbb2ee90 交替
MUMY    x2   Mummypunch      0xfc99300 vs 0x0         ← 一份有枪一份没有
PDPLANE x2   ParaDropWeapon  0x109d1e90 vs 0x0
```

推测这些是**按阵营/按地图存的类型副本**（CAR/SMIN/CMIN 这类中立可占领单位尤其多）。
**哪一份是引擎读档时真正用的，还没确认** ⇒ 写入要么全改，要么先验证。

## §4 指针从哪儿来（这是换枪的真实瓶颈）

### 4.1 指针是"进程地址"，不是存档偏移

`X+0x874` 的值是 `0x0C131E90` 这种 200MB 级地址，而明文只有 27MB。
**同一个档里**：一把武器恒定一个值，不同武器必然不同值（§3.1）。
**不同档之间不通用**：

```
120mm  5_修改.SAV / 65_修改.SAV / 65_武器测试.SAV  →  全是 0x109E9D40
        ALL01UMD.sav（战役）                       →  0x02BBEAC0
        QS_铁峰*.SAV（任务）                        →  0x16ED7560
```

⇒ 遭遇战一套、战役一套、任务一套，各档地址空间不同。
**结论：不能跨档抄指针，也不能自己算，只能从同一个档里借。**

### 4.2 覆盖率：本档 213 把武器里只有 122 把（57%）有现成指针

能借到指针 = 这个档里至少有一个类型在用这把武器。借不到的多是
`AGGattling*` / `AAGattCann*` 这类只有 AI 或特定建筑用的武器。

### 4.3 没有"名字 → 指针"的注册表

试过三种找法，都不成立：
- 武器对象内部**不含**自己的指针（125 把里 0 命中）
- 全档没有 213 长的指针数组（连续递增指针段最长 128，且是别的对象池）
- 指针出现次数平均 2.8 次，除类型对象外只在武器区里零星出现

⇒ 想要 100% 覆盖，只能另找路子（见 §6）。

## §5 还没验证的事（**写入之前必须先做**）

1. **改了到底生不生效？** 换了指针，游戏读档后是认新武器，还是按 rules 重新绑定？
   —— 这一步只能进游戏实测（改一个兵，打一枪看伤害/弹道）。
2. **已存在的实例会不会跟着变？** 地图上已经摆好的单位，可能在实例里也存了一份
   当前武器指针（M60 的指针在全档出现 2 次，第二次在 `0x12D992C`，很可能就是实例副本）。
   如果是这样，只改类型对象对**已存在**的兵无效，只对新造的兵有效。
3. **指针失效会不会崩？** 如果读档时引擎会按指针去解引用，写错一个字节就是直接崩。
   这是本项目**风险最高**的一类写入（比武器表定长写高一个数量级）。
4. **重名副本改哪份？** 见 §3.3。

## §6 下一步建议（按顺序，每步都能独立验收）

1. **先做只读展示**（零风险）：第 11 页加一列"哪些型号用这把武器"，
   用 `X+0x874` 反查即可。玩家能立刻看到"这把枪谁在用"，也顺便验证读数对不对。
2. **再做"换枪"的最小实验**：只支持一个方向——把某类型的 Primary 换成**同档已存在**的
   某把武器（借用指针），写前自动备份，写完立刻回读校验。
   进游戏验证 §5.1 / §5.2 两条，再决定要不要开放给玩家。
3. **补覆盖率**（如果玩家抱怨"想换的枪不在列表里"）：
   可以考虑"先用某类型临时占用 → 存盘 → 用它的指针"这种迂回，或去逆向
   引擎的指针重定位逻辑（那是另一个量级的活）。
